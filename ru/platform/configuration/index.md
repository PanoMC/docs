# Руководство по настройке

Pano использует файл конфигурации в формате **HOCON** (Human-Optimized Config Object Notation) для управления своими настройками.  
HOCON похож на JSON, но его легче читать — он поддерживает комментарии, строки без кавычек и висячие запятые.  
Подробнее о формате:  
 [Документация Lightbend HOCON](https://github.com/lightbend/config/blob/main/HOCON.md)

При первом запуске Pano автоматически создает файл конфигурации с именем **`config.conf`** в той же директории, что и ваш **`Pano-<версия>.jar`**.  
По умолчанию Pano ищет этот файл с помощью:

```kotlin
System.getProperty("pano.configFile", "config.conf")
```

Это означает, что вы можете указать **собственный путь к конфигурации**, используя параметр JVM **`-Dpano.configFile`**, например:

```bash
java -Dpano.configFile=/path/to/custom.conf -jar Pano-1.0.0.jar
```

Если путь не указан, Pano будет использовать файл `config.conf` по умолчанию в той же папке, что и JAR-файл.

Во время **процесса установки** некоторые значения, такие как данные базы данных, учетные данные администратора и URL-адреса, автоматически **записываются или перезаписываются**.  
Если вы измените их вручную, Pano может **перезаписать** их во время запуска или будущих обновлений.  
Редактируйте только то, что понимаете, и всегда делайте резервную копию перед внесением изменений.

## Автоматические миграции

При каждом запуске Pano проверяет поле **`config-version`** в вашей конфигурации. Если версия в файле старше требований текущей версии Pano, приложение **автоматически выполнит необходимые миграции**. Это гарантирует, что ваша конфигурация и база данных останутся совместимыми с последними функциями и обновлениями безопасности без ручного вмешательства.
## Общие настройки

```jsonc
# Версия конфигурации, используемая для миграций (НЕ меняйте вручную)
config-version = <int>

# Включить или отключить режим разработки (по умолчанию: false)
development-mode = false

# Код языка интерфейса (добавляется/редактируется через панель администратора)
locale = "en-US"

# Публичный URL вашего веб-сайта (требуется для писем, файлов cookie и т. д.)
website-url = "http://yourdomain.com"

# Как используется эта установка: "WEBSITE", "SERVERS" или "BOTH" (по умолчанию: "BOTH")
usage-mode = "BOTH"

# Разрешить пользователям выбирать предпочтительный язык (по умолчанию: true)
allow-user-locale-selection = true

# Соглашение о регистрации, показываемое пользователям (поддерживает HTML)
register-agreement = ""

# Название и описание веб-сайта
website-name = ""
website-description = ""

# Email службы поддержки, используемый для уведомлений и сброса пароля
support-email = ""

# Информация о сервере Minecraft, показываемая игрокам
server-ip-address = "play.ipadress.com"
server-game-version = "1.8.x"

# SEO ключевые слова
keywords = []
```

**Советы**

- `config-version`: используется внутри для миграций — **не переименовывайте и не редактируйте его**.
- `development-mode`: по умолчанию **false** для производительности и безопасности; устанавливайте **true** только для отладки.
- `locale`: используйте короткие коды, такие как `en-US`, `ru` или `tr` (языки можно добавить в панели).
- `website-url`: базовый URL вашего сайта. Это **обязательно** для генерации системных писем, управления файлами cookie сессий и других функций платформы.
- `usage-mode`: как используется эта установка. Значение выбирается на первом экране мастера настройки и в любой момент меняется в разделе **Панель → Настройки → Платформа → Предпочтения** (три выбираемых блока).
  - `"WEBSITE"`: только веб-сайт — классический вариант Pano.
  - `"SERVERS"`: только управление серверами Minecraft — продуктом становится панель. В боковом меню скрываются **Посты**, **Тикеты** и **Просмотр**, а все публичные адреса перенаправляются на `/panel`.
  - `"BOTH"`: веб-сайт + управление серверами. Значение по умолчанию; существующие установки мигрируют именно на него — их поведение не меняется.
  - В режиме `"SERVERS"` Pano вообще не запускает процесс темы: у панели есть [собственная страница входа](../server-management/#вход-без-саита) по адресу `/panel/login`. Переключение режима здесь запускает или останавливает тему без перезапуска.
- `allow-user-locale-selection`: включает/отключает возможность выбора пользователями собственного языка из доступных локалей (по умолчанию: `true`). Можно управлять в **Панель → Настройки → Платформа → Предпочтения**.
- `register-agreement`: определяет условия или правила, показываемые при регистрации пользователя. Это поле **поддерживает HTML-теги** для форматирования.
- `server-ip-address`: отображается в вашей теме — игроки могут **скопировать его и использовать для входа** на ваш сервер Minecraft.

> Нужно на время отключить публичный сайт? У блока `maintenance` есть отдельная страница: [Режим обслуживания →](../maintenance/).
## Тема

```jsonc
current-theme = "vanilla-theme"
```

**Детали**

- Определяет, какая тема активна.
- Если используется неверный ID темы, **Pano возвращается к `vanilla-theme`**.
- Можно изменить через **Панель → Вид → Темы**.
## Подключение Minecraft-сервера

```jsonc
mc-server-connection {
  heartbeat-interval-seconds = 25
  heartbeat-timeout-seconds = 75
}
```

**Детали**

- Heartbeat на уровне приложения, который **сам Pano** отправляет каждому подключённому
  Minecraft-серверу (через `pano-mc-plugin`). Это отдельно от — и в дополнение к — собственным
  `heartbeat-interval` / `heartbeat-timeout` плагина в его **собственном** `config.conf`: обе стороны
  отправляют ping независимо, каждая по своему расписанию. О том, как эти два heartbeat'а
  взаимодействуют с тайм-аутом простоя обратного прокси, см.
  [Обратный прокси: поддержание WebSocket-соединения](server/#обратныи-прокси-поддержание-websocket-соединения).
- `heartbeat-interval-seconds`: количество секунд между heartbeat-ping, которые Pano отправляет
  каждому подключённому Minecraft-серверу. По умолчанию **25**.
- `heartbeat-timeout-seconds`: сколько секунд ждать pong, прежде чем Pano сочтёт соединение с этим
  Minecraft-сервером мёртвым и закроет его. По умолчанию **75**.
- Оба значения проверяются при запуске: `heartbeat-interval-seconds` должен быть больше `0` и не больше
  **55**; `heartbeat-timeout-seconds` должен быть как минимум **вдвое больше** интервала. Пара, выходящая
  за эти границы, не отклоняется молча — Pano записывает предупреждение и возвращается к значениям по
  умолчанию **25s** / **75s** для обоих параметров вместо отказа при запуске. Про (чуть более строгое)
  правило стороны плагина см.
  [Обратный прокси: поддержание WebSocket-соединения](server/#обратныи-прокси-поддержание-websocket-соединения).
## Локальный узел (Local Node)

```jsonc
local-node {
  enabled = true
  jar-path = null
  java-path = null
  stop-with-pano = false
}
```

**Детали**

- Управляет демоном `pano-node`, который Pano может запускать **на своей собственной машине**;
  настраивается одной кнопкой в **Панель → Серверы → Узлы → Локальный узел**. Именно этот демон
  устанавливает *управляемые* Minecraft-серверы и следит за ними; см.
  [Управление серверами →](../server-management/).
- Демон всегда работает как **отдельный процесс**, а не внутри JVM самого Pano — в этом и смысл:
  перезапуск или обновление Pano не должны отключать Minecraft-серверы, которыми он управляет.
- `enabled`: `false` полностью запрещает Pano запускать локальный узел и следить за ним. Панель в
  этом случае показывает локальный узел как отключённый. По умолчанию **true**.
- `jar-path`: явный путь к `pano-node.jar`. Если оставить пустым, Pano ищет файл рядом со своим
  собственным jar и в рабочем каталоге, а иначе скачивает `pano-node.jar`, опубликованный вместе с
  той версией Pano, на которой он работает, и проверяет его по опубликованному рядом
  `pano-node.jar.sha256`.
- `java-path`: каталог Java **17 или новее** (либо сам файл `java` внутри него), с которым
  запускается демон. Если оставить пустым, Pano ищет сам: JVM, на которой он работает, `JAVA_HOME`,
  `/usr/lib/jvm`, `/Library/Java/JavaVirtualMachines`, обычные расположения в `C:\Program Files` и
  `java` в `PATH` — после чего выбирает самую новую из найденных. Это отдельная настройка, потому
  что **сам Pano работает на Java 11+, а `pano-node.jar` требует 17+**: на хосте с Java 11 передача
  демону собственной JVM Pano означает падение с `UnsupportedClassVersionError` при каждом запуске.
  Если подходящей версии нет, настройка локального узла завершается понятной ошибкой вместо
  бесконечных попыток, а **Панель → Серверы → Узлы** показывает причину.
- `stop-with-pano`: останавливать ли демон вместе с Pano. По умолчанию **false**, то есть
  управляемые серверы продолжают работать при перезапуске панели — администратор, перезапускающий
  Pano, не просил отключать игроков. Ставьте `true`, только если хотите, чтобы всё выключалось
  вместе.
## Управляемые серверы (Managed Servers)

```jsonc
managed-servers {
  plugin-jar-dir = null
  node-auto-update = true
  accept-agent-links = true
}
```

**Детали**

- Настройки Minecraft-серверов, которые Pano устанавливает и запускает через узел; см.
  [Управляемые серверы →](../server-management/#управляемые-серверы).
- В каждый созданный ею управляемый сервер Pano ставит **плагин Pano MC**, чтобы сервер, который она
  запускает, был и сервером, с которым она может общаться. По умолчанию берётся самый свежий
  опубликованный выпуск плагина.
- `plugin-jar-dir`: каталог с локально собранными jar-файлами `pano-mc-plugin`, которые надо
  использовать **вместо** скачивания. Укажите на рабочую копию `pano-mc-plugin` — и самый свежий
  найденный там `<module>/build/libs/pano-<platform>-*.jar` будет копироваться в каждый
  устанавливаемый Pano сервер. Это настройка для **разработки плагина**; на настоящей установке
  оставьте её пустой, и Pano возьмёт самый свежий опубликованный выпуск.
- `node-auto-update`: обновляет ли Pano демон `pano-node` узла — и каждого **Pano Agent** — до
  версии, которую раздаёт сама, как только узел подключается с более старой. По умолчанию **true**.
  Узел скачивает новый демон с Pano, проверяет контрольную сумму и перезапускается; Minecraft-серверы
  продолжают работать. Pano пробует **не чаще одного раза на узел и версию за 30 минут**, никогда —
  пока узел выполняет задачу (установку, импорт, резервное копирование; повторная проверка каждые
  5 минут), и записывает каждое автоматическое обновление в журнал действий. Поставьте `false`, чтобы
  обновлять узлы только вручную в **Панель → Серверы → Узлы**. **Панель → Настройки → Обновления**
  пишет этот же ключ.
- `accept-agent-links`: принимает ли Pano новые подключения **Pano Agent** — переключатель в окне
  **Связать с Pano Agent** пишет этот же ключ. По умолчанию **true**. При `false` окно не выдаёт
  код, все уже показанные коды сразу перестают действовать, а агент, пытающийся подключиться с
  таким кодом, получает отказ точно так же, как при неверном коде. Уже связанные агенты продолжают
  работать, а подключение узла по коду узла это не затрагивает. См.
  [Pano Agent →](../server-management/pano-node/#the-pano-agent).
## Источники плагинов (Plugin Sources)

```jsonc
plugin-sources {
  curseforge-api-key = null
}
```

**Детали**

- Где панель ищет плагины и моды для установки на управляемый сервер — вкладка **Каталог** на
  странице плагинов сервера. См. [Плагины и моды →](../server-management/#плагины-и-моды).
- **Modrinth** и **Hangar** не требуют ключа и включены всегда. Настраивать для них ничего не нужно.
- `curseforge-api-key`: **ключ CurseForge Eternal API** включает источник CurseForge. CurseForge
  требует, чтобы каждое приложение пользовалось собственным ключом, поэтому Pano не может поставлять
  его в комплекте — запросите свой на [console.curseforge.com](https://console.curseforge.com) и
  вставьте сюда. По умолчанию **пусто**, то есть источник выключен: панель показывает CurseForge
  недоступным с указанием причины и ищет по двум остальным.
- Проект CurseForge, автор которого запретил сторонние скачивания, не предлагает вообще никаких
  файлов. Он всё равно показан в списке, но установить из него ничего нельзя — скачайте его с
  CurseForge и загрузите jar через [файловый менеджер](../server-management/#фаилы).
