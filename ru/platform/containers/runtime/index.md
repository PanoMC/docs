# Среда выполнения контейнера

Как Pano ведёт себя в контейнере: перезапуски и обновления, Java, память и пользователи.

> [!WARNING]
> **Ещё не выпущено.** Режим контейнера появится вместе с образами и пока не входит ни в один релиз
> Pano. См. [Запуск Pano в контейнерах](../).

## Режим контейнера {#container-mode}

Вне контейнера перезапуск или обновление из панели запускает новый отсоединённый процесс `java`, а
старый завершается. В контейнере это остановило бы контейнер: когда основной процесс завершается,
контейнер тоже завершается.

В режиме контейнера Pano поступает иначе:

1. Готовит новый jar в `/data` и записывает имя его файла в `/data/.pano-jar`.
2. Завершается с кодом **75**.
3. Лаунчер образа (работает как PID 1 под `tini`) видит код 75 и запускает jar, указанный в
   `/data/.pano-jar`. Контейнер продолжает работать.

Любой другой код завершения, как обычно, завершает контейнер, поэтому ваша политика перезапуска
(например, `--restart unless-stopped`) по-прежнему обрабатывает сбои. Pano Host считает выход с кодом 75
плановым перезапуском, а не сбоем.

## Не используйте `-bg` {#never-use-bg}

[`-bg`](../../installation/) заставляет Pano перезапустить себя отсоединённым процессом и завершиться.
В контейнере это завершение останавливает контейнер. Образы никогда не передают `-bg`; не добавляйте его.

## Версия Java {#java-version}

Pano ориентирован на **Java 11**, поэтому Java 11 — его минимум, и в каждом семействе runtime есть
`jre11`. Более новые версии Java тоже работают; выберите новую, если она нужна вашему плагину.
[Управляемым серверам](../../server-management/managed-servers/) на локальном `pano-node` нужна Java 17 или новее.

Pano Host запускает новый инстанс на минимальной Java, нужной его версии Pano (определяется по jar), и
позволяет выбрать более новую. Более старая отклоняется.

## glibc, а не Alpine {#glibc-not-alpine}

Образы построены на базе **glibc** (Eclipse Temurin на Ubuntu). Некоторые нативные библиотеки Pano,
например хеширование паролей Argon2, существуют только в сборках для glibc. В образе на musl, таком как
**Alpine**, вход в систему не работает. Если собираете свой образ, начинайте с Java-образа на glibc.

## Память {#memory}

Heap Java следует лимиту памяти контейнера (`-XX:MaxRAMPercentage`), поэтому всегда задавайте его
(`--memory`). Лимит покрывает JVM **и** процессы Bun, которые рендерят UI; как Pano использует память,
описано в разделе [Память и лимиты](../../configuration/memory/). Pano Host задаёт heap примерно в 75 %
памяти инстанса.

Образы поставляются с Bun, поэтому Pano не скачивает его при первом запуске.

## Непривилегированный пользователь {#non-root}

Образы запускают Pano от **непривилегированного** пользователя и не требуют дополнительных
возможностей. Pano Host запускает инстансы со сброшенными capabilities, `no-new-privileges`, корневой
файловой системой только для чтения, записываемым `/data` и временным `/tmp`. Если запускаете с
`--user`, убедитесь, что этот пользователь может писать в `/data`.
