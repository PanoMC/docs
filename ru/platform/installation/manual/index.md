# Ручная установка (.jar)

Запустите `.jar` файл Pano сами, так же, как **Spigot** или **Paper**. От вас нужны **Java 11 или новее** и
база данных MySQL / MariaDB, а за тем, чтобы Pano продолжал работать, следите вы. Хотите, чтобы всё
сделали за вас? Используйте [установку одной командой](../installer/) или [Docker](../../containers/).

## Загрузка Pano

Вы можете получить последнюю версию Pano с официального сайта:

- [Скачать последнюю версию →](https://panomc.com/downloads)
- Для старых версий посетите [GitHub Releases](https://github.com/PanoMC/Pano/releases)

Pano распространяется в виде **`.jar`** файла — точно так же, как **Spigot** или **Paper**.  
После загрузки сохраните файл в удобном месте (например, в специальной папке, такой как `/pano`).

> [!NOTE]
> При первом запуске Pano извлечет необходимые файлы, создаст директории (например, `plugins/` и `themes/`), а также загрузит необходимые зависимости. Настоятельно рекомендуется запускать его в отдельной папке.

## Запуск Pano

Чтобы запустить Pano, откройте терминал (или командную строку) и выполните:

```bash
java -jar Pano-<version>.jar
```

Если доступна графическая оболочка, **Pano автоматически запустит графический интерфейс (GUI)**.  
В противном случае работа продолжится в консольном режиме.

### Поведение GUI

- **Двойной щелчок** по `.jar` файлу попытается автоматически запустить GUI.
- Используйте флаг **`-nogui`**, если предпочитаете запускать Pano в консольном режиме:

```bash
  java -jar Pano-<version>.jar -nogui
```

- Встроенный GUI включает минимальную консоль **только для команд Pano**.

Если GUI не может запуститься (например, на сервере без графической оболочки), консоль продолжит работу автоматически.

### Фоновый режим (`-bg`) {#background-mode-bg}

Если вы запускаете Pano из терминала или SSH-сессии, при её закрытии процесс обычно завершается. Флаг **`-bg`** отвязывает Pano от запустившего его терминала, и процесс продолжает работу самостоятельно:

```bash
java -jar Pano-<version>.jar -bg
```

При указании `-bg` процесс-запускатор пересоздаёт себя в виде отвязанного дочернего процесса и завершает работу. Стандартные потоки вывода и ошибок отвязанного процесса отбрасываются — смотрите папку `logs/` для логов работы.

`-bg` и `-nogui` **независимы** друг от друга:

| Флаги | GUI | Отвязан от терминала |
| --- | --- | --- |
| _(нет)_ | Да | Нет |
| `-nogui` | Нет | Нет |
| `-bg` | Да | Да |
| `-bg -nogui` | Нет | Да |

> [!TIP]
> Когда вы запускаете обновление или перезапуск платформы из панели, и платформа в данный момент **привязана к терминалу**, в окне подтверждения появляется переключатель «Перезапустить в фоновом режиме». Включив его, вы гарантируете, что новый процесс будет отвязан от терминала — удобно, если вы хотите сразу закрыть SSH-сессию.

> [!NOTE]
> У процесса, запущенного с `-bg`, нет интерактивного stdin, поэтому консольный считыватель JLine не запускается. Вводите команды через интерфейс панели или, если не передан `-nogui`, через встроенную GUI-консоль.
