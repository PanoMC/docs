# Права и оповещения

## Права доступа {#permissions}

Выдаются в разделе **Панель → Права доступа**, как и все остальные права.

| Право | Узел | Что разрешает |
| --- | --- | --- |
| Управление серверами | `pano.panel.manage.servers` | Видеть, привязывать и удалять серверы; обзор и настройки |
| Управление консолью сервера | `pano.panel.manage.server.console` | Консоль и команды |
| Управление питанием сервера | `pano.panel.manage.server.power` | Запуск, остановка, перезапуск, завершение |
| Управление игроками сервера | `pano.panel.manage.server.players` | Список игроков и действия над ними |
| Управление плагинами сервера | `pano.panel.manage.server.plugins` | Плагины и моды |
| Управление файлами сервера | `pano.panel.manage.server.files` | Файловый менеджер |
| Управление резервными копиями сервера | `pano.panel.manage.server.backups` | Резервные копии и восстановление |
| Управление расписаниями сервера | `pano.panel.manage.server.schedules` | Расписания |
| Управление запуском сервера | `pano.panel.manage.server.startup` | Память, Java, порт, аргументы JVM |
| Создание серверов | `pano.panel.create.servers` | Создание, переустановка, смена ПО |
| Управление узлами | `pano.panel.manage.nodes` | Добавление, обновление, удаление узлов |

**Только для некоторых серверов:** любое право `pano.panel.manage.server.*` можно ограничить
отдельными серверами через список **Какие серверы**. Оставьте его пустым — и право действует для всех
серверов.

**Запрещённые команды:** право на консоль может нести список команд, которые ему нельзя отправлять
никогда:

```jsonc
"denyCommands": ["op", "deop", "stop", "whitelist*"]
```

Сравнивается первое слово, регистр не учитывается; `*` означает совпадение по началу. Учётные записи
с правом `*` не блокируются никогда.

> Доступ к консоли равен правам оператора — выдавайте его так же осторожно, как OP, и ограничивайте
> отдельными серверами.

Вкладка **Действия** каждого сервера показывает, кто что сделал: команды, действия с питанием и над
игроками, изменения плагинов и файлов, резервные копии и запуски по расписанию. То, что Pano сделала
сама — падение, запуск по расписанию, автоматическое обновление, — показано как **Система**. Частота
действий
ограничена на пользователя и на сервер — например, 10 команд за 10 секунд и 3 резервные копии за
10 минут.

## Оповещения {#alerts}

| Оповещение | Когда срабатывает |
| --- | --- |
| **Сервер упал** | Сервер завершился, хотя его об этом не просили. |
| **Узел недоступен** | Узел перестал отвечать. |
| **Ошибка резервного копирования** | Резервная копия не завершилась. |
| **Мало места на диске** | Диск узла заполнен более чем на 90%. |
| **Низкий TPS** | Сервер держался ниже 15 TPS. |
| **Ошибка расписания** | Запуск по расписанию завершился ошибкой. |
| **Обновления плагинов** | Доступны более новые сборки плагинов (проверяется раз в сутки). |

Каждое оповещение становится уведомлением в панели для всех, кто управляет серверами, и какое-то
время не повторяется. **Настройки → Платформа → Оповещения о серверах** включает и выключает каждый
вид и может также отправлять его по e-mail. Карточка **Оповещения** в настройках сервера может
включить или выключить его оповещения только для этого сервера.
